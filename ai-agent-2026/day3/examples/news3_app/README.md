# 예시 · Coding Agent와 일하는 습관대로 만든 '뉴스 3개' 웹앱

강의 21~22쪽의 과제 **"주제를 입력하면 뉴스 3개를 골라 요약해 보여 주는 웹앱을 만들어 줘"** 를, 22쪽의 습관 다섯 가지를 지키며 만든 실제 결과물입니다. 단계마다 **Coding Agent에게 보낸 문장**, **사람이 확인한 것**, **실제 실행 결과**, **커밋**을 그대로 적었습니다.

> 이 예시는 강사가 Claude(Coding Agent 역할)와 함께 2026년 10월 16일에 습관 순서대로 실제로 만들고 테스트를 돌린 것입니다. 실제 Claude API로 판단하는 부분(`claude_judge`)은 키 없이 만들어 **실행해 보지 않았습니다.** 키가 없으면 모의 판단으로 동작합니다.

> **Windows라면 WSL에서:** [WSL에서 시작하는 실습 환경](../../wsl_setup.md) 1~3단계를 따르면 이 예시를 받아 테스트 · 실행까지 합니다. 앱을 띄운 뒤 Windows 브라우저에서 `http://127.0.0.1:8000`을 엽니다.

## 한눈에 보기

| 습관 | 이 예시에서 |
| --- | --- |
| 가장 작은 버전부터, 파일 3개 이내로 | 한 번에 웹앱 전체가 아니라 **기사 고르는 함수 하나 + 테스트**부터. 커밋마다 바뀐 파일 3개 이내 |
| 테스트를 먼저 쓰게 한다 | 1단계에서 테스트만 쓰고 **실패하는 것부터 확인** → 4단계에서 찾은 버그도 **테스트를 먼저 추가**하고 고침 |
| 바뀐 코드(diff)를 읽고 승인 | 4단계 버그 수정은 diff 7줄만 읽고 승인 |
| 자주 커밋해 되돌릴 지점을 만든다 | 단계마다 커밋 6개 |
| API 키는 .env · 환경 변수에만 | 코드에는 키가 없음. `.env.example`만 만들고 `.env`는 `.gitignore` |

## 실행해 보기

Python 3.10 이상만 있으면 됩니다 (추가 설치 없음).

```bash
cd day3/examples/news3_app
python3 -m unittest discover -s tests        # 테스트 10개 → OK
python3 app.py                               # 브라우저에서 http://127.0.0.1:8000
```

화면에 주제를 쓰고, **오늘 날짜 칸을 반드시 `2026-10-18`로 바꾼 뒤** [`sample_articles.txt`](sample_articles.txt)의 9줄을 붙여 넣고 **3개 고르기**를 누릅니다. 날짜 칸의 기본값은 실행하는 날이라, 그대로 두면 예시 기사(10/13~10/18)가 미래 기사로 처리돼 아래 결과와 달라집니다. 실제 AI로 판단하게 하려면 `.env.example`을 `.env`로 복사해 키를 넣습니다 (지출 상한 먼저).

| 파일 | 하는 일 |
| --- | --- |
| [`pick.py`](pick.py) | **규칙(Workflow):** 기사 줄 읽기, 최근 7일만, 같은 소식 합치기 → 남은 것 중 무엇이 중요한지는 `judge`(AI)에게 |
| [`llm.py`](llm.py) | **판단(Agent):** 키가 있으면 Claude API, 없으면 모의 판단. 키는 `.env`에서만 읽음 |
| [`app.py`](app.py) | 웹 화면 한 장. 빈 입력이면 AI를 부르지 않음 |
| [`tests/test_pick.py`](tests/test_pick.py) | 테스트 10개. AI는 가짜(`fake_judge`)로 바꿔 실제 API를 부르지 않음 |

## 만든 과정 · 6단계

### 0단계 · 계획부터 (코드 없음)

**보낸 문장**

```
주제를 입력하면 뉴스 3개를 골라 보여 주는 웹앱을 만들 거야. 바로 코드를 쓰지 말고 계획부터 보여 줘.
- 가장 작은 버전부터: 첫 단계는 '기사 목록에서 3개 고르는 함수 하나와 테스트'만. 파일 3개 이내.
- 규칙으로 되는 일(7일 지난 기사 빼기, 같은 소식 합치기)은 코드로, 무엇이 중요한지는 AI가 판단.
- 키는 환경 변수로만. 파일 삭제 · 배포는 먼저 물어봐.
```

**사람이 확인한 것:** 계획이 '함수 → 테스트 → 웹 화면' 순서인가? 첫 단계에 웹 화면 · 배포가 들어 있지 않은가? → 승인

### 1단계 · 테스트 먼저 (아직 실패)

**보낸 문장**

```
코드를 쓰기 전에 테스트부터 써 줘. 7일 지난 기사 제외, 같은 소식 합치기, 3개가 안 되면 있는 만큼만, 빈 입력.
AI 판단은 가짜 함수로 바꿔서 실제 API를 부르지 않게. 테스트를 돌려 실패하는 것을 보여 줘.
```

**실제 실행 결과** — 함수가 아직 비어 있어 6개 모두 실패하는 것이 정상입니다.

```
Ran 6 tests in 0.004s

FAILED (errors=6)
```

**커밋** `테스트 먼저: 7일 제외 · 중복 합치기 · 3개 미만 · 빈 입력 (아직 실패)` — 바뀐 파일 3개 (`.gitignore`, `pick.py`, `tests/test_pick.py`)

### 2단계 · 테스트를 통과시키기

**보낸 문장**

```
이제 테스트가 통과하도록 pick.py만 채워 줘. 다른 파일은 건드리지 마.
```

**실제 실행 결과**

```
Ran 6 tests in 0.001s

OK
```

**커밋** `기사 선별 함수: 규칙(7일 · 중복)은 코드로, 중요도 판단은 judge에게 — 테스트 6개 통과`

### 3단계 · AI 판단 연결 (키는 .env에만)

**보낸 문장**

```
judge를 실제 Claude API로 연결해 줘. 키는 ANTHROPIC_API_KEY 환경 변수나 .env에서만 읽고, .env.example만 만들어.
키가 없으면 모의 판단으로 돌아가게. .env 파일은 열거나 출력하지 마.
```

**사람이 확인한 것:** 코드 어디에도 키가 없는가? `.gitignore`에 `.env`가 있는가? → 테스트 8개 OK

**커밋** `AI 판단 연결: 키는 .env에서만, 키가 없으면 모의 판단 — 테스트 8개 통과`

### 4단계 · 웹 화면 → 직접 돌려 보고 버그 발견 → 테스트 먼저 추가하고 고침

**보낸 문장**

```
웹 화면 한 장을 만들어 줘. 주제 · 오늘 날짜 · 기사 목록을 넣으면 카드로 보여 주고, 빈 입력이면 AI를 부르지 마.
```

**커밋** `웹 화면 한 장: 빈 입력이면 AI를 부르지 않음, 모의/실제 판단 표시`

**직접 돌려 보니:** `sample_articles.txt`의 실제 기사 9개를 넣자, 같은 소식인 1번(정부 가이드라인 초안 공개)과 2번(가이드라인 초안 주요 내용)이 **둘 다** 뽑혔습니다. 테스트의 짧은 제목에서는 합쳐졌지만, 실제 기사처럼 **제목이 길면 못 합치는 버그**였습니다.

**보낸 문장 ('알아서 고쳐 줘' 대신)**

```
제목이 긴 실제 기사에서 같은 소식이 안 합쳐져. 고치기 전에 이 경우를 재현하는 테스트를 먼저 추가해서 실패하는 걸 보여 줘.
그다음 고치고, 바뀐 부분(diff)만 보여 줘.
```

**실제 실행 결과 · 고치기 전**

```
FAIL: test_merge_same_story_with_long_titles
AssertionError: 3 != 2
FAILED (failures=1)
```

**사람이 읽은 diff (이것만 읽고 승인)**

```diff
+GENERIC = {"AI"}  # 거의 모든 기사에 나오는 말은 같은 소식 판단에서 뺀다
+
 def _same_story(a, b):
-    wa, wb = _words(a["title"]), _words(b["title"])
-    return len(wa & wb) / max(1, len(wa | wb)) >= 0.3
+    """두 제목이 'AI'를 뺀 낱말을 3개 이상 함께 쓰면 같은 소식으로 본다."""
+    wa, wb = _words(a["title"]) - GENERIC, _words(b["title"]) - GENERIC
+    return len(wa & wb) >= 3
```

**확인한 것:** 바뀐 곳이 '같은 소식 판단' 함수 하나뿐인가? 기존 테스트도 그대로 통과하나? → 9개 OK

**커밋** `버그 수정: 제목이 길면 같은 소식을 못 합치던 문제 — 테스트를 먼저 추가하고 고침 (테스트 9개 통과)`

### 5단계 · 결과를 보고 한 번 더

주제를 `반도체 투자`로 바꿔 보니, 모의 판단이 관련 없는 기사까지 넣어 **3개를 억지로 채웠습니다.** 실제 AI에게 준 지시("관련이 낮으면 3개를 채우지 않는다")와 맞지 않아, 같은 방식으로 테스트를 먼저 추가하고 고쳤습니다.

**커밋** `모의 판단도 관련 없는 기사로 3개를 채우지 않게 (테스트 10개 통과)`

**최종 실행 결과** (오늘 날짜 2026-10-18, 기사 9개, 모의 판단)

| 주제 | 고른 기사 |
| --- | --- |
| `공공 행정 민원` | 2번 가이드라인 초안 주요 내용 (1번과 합침) · 3번 한빛시 민원 상담 AI 비서 · 6번 행정 데이터 200종 개방 — **3개** |
| `반도체 투자` | 5번 AI 반도체 스타트업 투자 유치 — **1개** (억지로 채우지 않음) |

7번(10/05)은 두 경우 모두 7일이 지나 빠졌습니다.

위 번호는 만들 당시의 기록이라 이 저장소에는 들어 있지 않습니다. 내 폴더에서 만들 때는 `git log --oneline`으로 내 커밋 번호를 보고, 필요하면 그 시점으로 돌아갈 수 있습니다(`git reset --hard <번호>` — 저장하지 않은 변경은 지워지니 주의). 이것이 '자주 커밋'의 이유입니다.

| --- | --- | --- |
| `뉴스 웹앱 전부 만들어 줘` | 파일 10개 이상, 어디가 틀렸는지 모름 | 0단계: 함수 하나 + 테스트부터, 파일 3개 이내 |
| `알아서 다 고쳐 줘` | 버그와 상관없는 곳까지 바뀜, 같은 버그가 다시 생겨도 모름 | 4단계: 재현 테스트 먼저 → 고침 → diff만 보여 줘 |
| (테스트 통과만 보고 끝) | 실제 기사에서 터지는 버그를 놓침 | 4단계: 화면에서 실제 자료로 직접 돌려 봄 |

| (모르는 명령을 그냥 허용) | 파일 삭제 · 설치가 몰래 일어날 수 있음 | 무엇을 실행하는지 읽고 허용. 삭제 · 배포는 먼저 묻게 |
