# 트랙 A · AI 판단이 들어간 웹앱 (기본+, 모두)

범용 AI 대화창에서 **한 화면짜리 웹앱**을 만듭니다. 버튼을 누르면 앱 안에서 AI가 판단해야 완주입니다. 화면만 있고 정해진 글이 나오면 목업입니다.

- 앱 안에서 AI를 부를 수 있는 도구를 씁니다 (예: Claude Artifacts).
- (선택) Stitch 같은 화면 설계 도구로 먼저 화면을 그려 볼 수 있습니다.
- 웹 검색이 꼭 필요한 일(뉴스 등)은 웹앱보다 [A0](A0_custom_agent.md)이 쉽습니다.

## 프롬프트 틀

```
다음 설계로 한 화면짜리 웹앱을 만들어 줘.
- 입력: [입력] (입력창 + 실행 버튼)
- 판단: 버튼을 누르면 앱 안에서 AI를 호출해 [Agent 판단]한다
- 결과: [결과 형식]을 카드로 보여 준다
- 판단 결과가 비어 있거나 실패하면 이유를 화면에 알려 준다
정해진 글을 미리 넣어 두지 말고, 입력이 바뀌면 결과도 바뀌게 해 줘.
```

**통째로 완성된 프롬프트 5개**(회의록 정리기 · 노트북 추천기 · 논문 판정기 · 공고 판정기 · 메일 분류기)는 [`../examples/project_examples.md`](../examples/project_examples.md)에 있고, 테스트 입력은 [`../data/test_inputs.md`](../data/test_inputs.md)에 있습니다.

## 만든 뒤 바로 확인

1. 테스트 입력 ①을 넣고 결과를 봅니다.
2. 테스트 입력 ②를 넣고 결과가 **달라지는지** 봅니다.
3. 같으면 목업입니다. 아래 문장을 보내 고칩니다.
   ```
   지금은 입력이 바뀌어도 결과가 같아. 정해진 글 대신 버튼을 누를 때마다 AI를 호출해서 판단하게 고쳐 줘.
   ```

## 다듬기 요청 예

| 하고 싶은 것 | 보낼 문장 |
| --- | --- |
| 판단 이유를 보이게 | `결과 카드마다 AI가 그렇게 판단한 이유를 한 줄씩 보여 줘` |
| 테스트를 편하게 | `입력창 아래에 '예시 넣기' 버튼을 두 개 만들어서 테스트 입력 ①, ②가 채워지게 해 줘` |
| 사람 확인 지점 | `'메일 초안 복사' 버튼을 누르면 "보내기 전에 내용을 확인하세요" 안내를 띄워 줘` |
| 실패 처리 | `입력이 비어 있으면 AI를 부르지 말고 '입력을 넣어 주세요'라고 보여 줘` |
