# 장면 0 · 어제 못 한 메신저 연결 — 디스코드로 비서 부르기

어제(DAY 2) 강의에서는 OpenClaw · Hermes를 **메신저와 연결하는 데까지 가지 못했습니다.** 오늘 오프닝에서 강사가 **디스코드(무료)** 로 연결하는 장면을 라이브로 보여 주고, 수업이 끝날 때 같은 비서에게 다시 말을 걸어 **기억**을 확인합니다.

```
① 디스코드 봇 만들기 (수업 전) → ② 비서에 연결 (라이브) → ③ 첫 메시지: 일 맡기기 → … 수업 … → ④ 마무리: '브리핑' 한 단어로 기억 확인 → ⑤ 정리
```

**수강생은 보기만 하면 됩니다.** 집에서 따라 할 분은 이 순서와 [메신저 연결 안내](../../day2/advanced/messengers.md)를 보세요. 왓츠앱 · 라인도 같은 안내에 있습니다.

---

## 왜 메신저인가 (1분 설명)

| | 어제 실습한 범용 AI | 메신저 비서 (오늘 연결) |
| --- | --- | --- |
| 말을 거는 곳 | 그 회사의 웹 · 앱 | 내가 늘 쓰는 메신저 (디스코드 · 왓츠앱 등) |
| 시작 | 내가 창을 열어야 | **늘 켜진 게이트웨이**가 메시지를 기다림 |
| 손발 | 회사가 허용한 도구 | 내 컴퓨터에서 명령 실행 · 파일 · 웹 |

메신저는 **통로**일 뿐이고, 판단은 같은 AI 모델이 합니다. 그래서 통로를 바꿔도 메모리와 스킬은 그대로 남습니다.

---

## ① 디스코드 봇 만들기 (수업 전, 화면 공유 끄고)

봇 토큰은 비밀번호라 이 단계는 **수업 전에** 해 둡니다. 두 비서용으로 봇을 2개 만듭니다.

1. [Discord Developer Portal](https://discord.com/developers/applications) → **New Application** → 이름 (`demo-hermes`, `demo-openclaw`)
2. **Bot** → **Reset Token** → 토큰을 메모장에 저장 · **Message Content Intent** 켜기 · **Server Members Intent** 켜기
3. **OAuth2 → URL Generator** → `bot`, `applications.commands` → 권한 View Channels · Send Messages · Read Message History · Embed Links · Attach Files → 주소를 열어 **수업용 디스코드 서버**에 초대
4. 디스코드 **설정 → 고급 → 개발자 모드** → 내 프로필 오른쪽 클릭 → **사용자 ID 복사**

## ② 비서에 연결 (라이브 · 5분)

강의 PC의 WSL에서 합니다. 토큰을 붙여 넣는 순간에만 화면 공유를 잠시 끕니다.

**Hermes** (`wsl -d hermes-live`)

```bash
hermes gateway setup    # Discord 선택 → 봇 토큰 → 허용 사용자: 내 사용자 ID
hermes gateway          # 게이트웨이 켜기 (이 탭은 수업 끝까지 열어 둠)
```

**OpenClaw** (`wsl -d openclaw`)

```bash
openclaw channels add            # 목록에서 Discord → 봇 토큰 (처음이면 플러그인 설치를 물어봄)
openclaw channels status --probe # 연결 확인
openclaw gateway status          # 게이트웨이가 도는지
```

- 디스코드에서 봇에게 **DM**을 보냅니다. Hermes는 DM에 바로 답합니다. 서버 채널에서는 `@봇이름`으로 불러야 합니다.
- OpenClaw가 짝 맞추기 코드를 보내면, 내 계정이므로 `openclaw pairing approve discord <코드>`로 승인합니다.

**보여 줄 것:** 허용 사용자 설정. "Hermes는 허용 목록이 비어 있으면 **아무에게도 답하지 않는다** — 명령 실행 도구를 가진 비서라서 기본이 '거절'입니다."

## ③ 첫 메시지 · 일 맡기기 (라이브 · 2분)

두 봇의 DM 창에 똑같이 보냅니다.

```
너는 내 개인 비서야. 앞으로 내가 "브리핑"이라고만 보내면 아래대로 해 줘.
- 최근 7일 AI 에이전트 관련 뉴스를 웹에서 찾는다
- 공공 행정 실무자에게 바로 영향을 주는 소식 3개를 고른다
- 각 소식은 제목 · 한 줄 이유 · 링크로 쓴다
- 출처를 확인할 수 없는 내용은 쓰지 않는다
이 규칙을 기억해 두고, 지금은 규칙을 한 줄로 요약만 해 줘.
```

**볼 것:** 규칙을 한 줄로 정확히 요약하나? 그다음 `브리핑`을 한 번 보내 결과까지 보여 줍니다(1~2분 걸림. 기다리는 동안 다음 슬라이드로 넘어가도 됩니다).

## ④ 마무리 · 기억 확인 (데모 시간 끝, 2분)

두 시간쯤 지난 수업 끝에 **같은 DM 창에** 보냅니다.

```
브리핑
```

| 확인 | 잘 된 결과라면 |
| --- | --- |
| 기억 | 규칙을 다시 설명하지 않았는데 3개 · 한 줄 이유 · 링크 형식으로 나옴 |
| Hermes 스킬 | WSL에서 스킬 폴더를 열어 새 파일이 생겼는지 (`ls -lt ~/.hermes/skills \| head`) |
| 안전 | 이어서 `지금 네가 도는 컴퓨터의 홈 폴더 목록을 보여 줘` → 실행 전에 허락을 구하나 (거절로 답함) |

**연결 문장:** "오늘 여러분이 만든 A0 에이전트는 **내가 부를 때** 일합니다. 메신저 비서는 **늘 켜져 기다리다가** 일합니다. 같은 지시문을 어디에 두느냐의 차이입니다."

## ⑤ 정리 (수업 뒤)

1. 디스코드 Developer Portal에서 두 봇 모두 **Reset Token**(기존 토큰 무효화) 또는 앱 삭제
2. 강의 PC의 WSL 환경 정리 ([강사 준비표 5번](../../instructor/wsl_demo_setup.md#5-수업이-끝나면--공용-pc-정리-10분))
3. ChatGPT 구독 로그인을 쓴 경우 WSL을 지우면 로그인 정보도 함께 사라집니다

## 막힐 때 (라이브 중 2분 규칙)

| 이럴 때 | 이렇게 |
| --- | --- |
| 봇이 오프라인 | 게이트웨이 탭이 켜져 있는지, Developer Portal에서 **Message Content Intent**가 켜져 있는지 |
| 봇이 답하지 않음 | 허용 사용자에 내 사용자 ID가 들어 있는지 (Hermes `~/.hermes/.env`의 `DISCORD_ALLOWED_USERS`) |
| 서버 채널에서만 안 됨 | DM으로 보내거나 `@봇이름`으로 부르기 |
| 2분 넘게 안 됨 | 연결은 수업 끝 데모 전에 다시 시도하고, 오프닝은 [메신저 연결 안내](../../day2/advanced/messengers.md) 화면으로 설명만 하고 넘어감 |
